ContextMenu opens a menu of actions for an area where the user right-clicks, or long-presses on a touch screen: a file, a row, a canvas. It opens at the pointer. The menu is the Figma "Popover" surface with the same items as [DropdownMenu](?path=/docs/components-dropdownmenu--docs). It is built on Radix Context Menu.

```tsx
import {
  ContextMenu,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuShortcut,
  ContextMenuTrigger,
} from '@holakirr/snow-ui'

<ContextMenu>
  <ContextMenuTrigger className="block rounded-16 border border-dashed p-6">
    Right-click here
  </ContextMenuTrigger>
  <ContextMenuContent>
    <ContextMenuItem onSelect={reload}>
      Reload
      <ContextMenuShortcut keys={['⌘', 'R']} separator="" />
    </ContextMenuItem>
    <ContextMenuItem onSelect={remove}>Delete</ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>
```

## When to use

- Shortcuts to actions on an object the user points at: a file, a table row, a card.
- Power-user actions that are also available somewhere else (a toolbar, a "more" menu).

## When not to use

- The only way to reach an action: right-click is hidden and the trigger isn't reachable with the keyboard. Use a [DropdownMenu](?path=/docs/components-dropdownmenu--docs) or a [Button](?path=/docs/components-button--docs), and add a context menu on top if you like.
- Picking a value for a form field: [Select](?path=/docs/components-input-select--docs).
- Content that isn't a list of actions: [Popover](?path=/docs/components-popover--docs).

## Anatomy

1. **Root** (`ContextMenu`): holds the open state. It renders nothing itself.
2. **Trigger** (`ContextMenuTrigger`): a `<span>` around the area that opens the menu; style it (e.g. `block`) to size the area.
3. **Content** (`ContextMenuContent`): the `role="menu"` panel, in a portal, at the pointer (Radix places it 2px to the right of the point, aligned to its top). At least 240px wide (`min-w-60`). The Figma Popover surface: 12px padding, a 16px radius, `background-3`, a 1px `surface-1` stroke and Glass 2. It doesn't scroll by default, since a scroll area would clip a submenu that isn't portalled. For a long menu, add `max-h-(--radix-context-menu-content-available-height) overflow-y-auto` and wrap submenus in `ContextMenuPortal`: it scrolls with the kit's scrollbar (`scrollbar-snow`).
4. **Item** (`ContextMenuItem`): 36px high (8px padding), a 12px radius, 14/20 text, 16px icons 8px apart. `variant="destructive"` (added in 5.2) makes it the kit's red row: text and icons in `red-text` (see [Destructive item](#destructive-item)). `inset` adds 32px of start padding.
5. **Checkbox item** (`ContextMenuCheckboxItem`) and **radio item** (`ContextMenuRadioItem`, in a `ContextMenuRadioGroup`): a 16px check mark in a slot 8px from the end, like Select's (the Figma selected item). Both kinds show the check; the role (`menuitemcheckbox`, `menuitemradio`) tells them apart.
   **Switch item** (`ContextMenuSwitchItem`, added in 5.2): a checkbox item that ends in the kit's Switch (28×16) instead of the check, as the kit's "Wrap Column" row. See [Switch item](#switch-item).
6. **Label** (`ContextMenuLabel`, optional): a group title, 14/20 `text-secondary`, 28px high (the kit's SearchPopup group title); takes `inset`.
7. **Group** (`ContextMenuGroup`, optional): groups items (no spacing of its own).
8. **Separator** (`ContextMenuSeparator`): a 1px `black-4` line, 7px under the item above and 8px over the item below: 16px between the groups' items, as the kit's item group (8px padding above and below, a 1px Black/4% stroke inside its bottom edge).
9. **Shortcut** (`ContextMenuShortcut`, optional): a `KBD` (12/16) at the end of an item, from `keys`, as the kit's plain text in `text-secondary` (Figma: "⌘C" in Black/40%, no key cap). `separator=""` joins symbol keys as in the kit (`⌘C`, not `⌘+C`); a `variant` (`solid`, `border`) brings back the KBD key cap.
10. **Submenu** (`ContextMenuSub`): a `ContextMenuSubTrigger` (an item with a 16px `text-secondary` chevron at the end and an optional `hint` with the current value before it, as in DropdownMenu) and a `ContextMenuSubContent` on the same surface. `ContextMenuPortal` is exported to portal it.

## States

- **Highlighted** (hover or keyboard focus): Black/4% fill. A sub trigger keeps it while its submenu is open.
- **Checked:** a check mark at the end (`checked` on a checkbox item, or the radio group's `value`); a switch item's switch is on (`primary` track, the thumb at the end).
- **Destructive** (`variant="destructive"`, added in 5.2): `red-text` text and icons, on the same Black/4% highlight; dimmed like any item when disabled.
- **Disabled** (`disabled` on an item): Black/20% text and a not-allowed cursor; the arrow keys and typeahead skip it.
- **Disabled trigger** (`disabled` on `ContextMenuTrigger`): the area opens no menu, and the browser's own menu shows instead.
- **Open and closed:** `open` / `onOpenChange` on `ContextMenu`. The trigger has `data-state="open"` while its menu is open.

## Switch item

Added in 5.2. `ContextMenuSwitchItem` is the kit's "Wrap Column" row: a setting that turns on and off, with the kit's Switch at the end of the item (a 28×16 track, `control-border` off and `primary` on, a 12px thumb that moves to the end; a Black/10% or Black/20% track when disabled). It takes the props of a checkbox item, with a boolean `checked` and `onCheckedChange(checked)`.

- **Semantics:** the item is the `menuitemcheckbox`, with `aria-checked`. The switch is a picture of that state (`aria-hidden`, no `role="switch"`): a menu item can't contain a control of its own, so don't put a [Switch](?path=/docs/components-input-switch--docs) in a `ContextMenuItem`.
- **Selecting** it (a click, Enter, Space) toggles it and closes the menu, as a checkbox item. To toggle in place, call `event.preventDefault()` in `onSelect`, as the story does.
- In right-to-left text the thumb moves to the left when on.

```tsx
<ContextMenuSwitchItem
  checked={wrap}
  onCheckedChange={setWrap}
  onSelect={(event) => event.preventDefault()}
>
  <TextAlignLeftIcon />
  Wrap column
</ContextMenuSwitchItem>
```

## Destructive item

Added in 5.2. `variant="destructive"` on `ContextMenuItem` marks an action that deletes or can't be undone, as the kit's red "Delete Property" row: the text and the icons (which take `currentColor`) are `red-text`, as AlertDialog's red action. `red-text` is #D42020 in light mode; in dark mode it is mixed with 40% white, so it keeps 4.5:1 on the item's highlight too. The role stays `menuitem`: say what the item does in its label ("Delete property"), not with the colour alone.

```tsx
<ContextMenuItem variant="destructive" onSelect={remove}>
  <TrashIcon />
  Delete property
</ContextMenuItem>
```

## Portal and theme

`ContextMenuContent` renders in a portal at the end of `<body>`, outside your layout. So it takes the theme of `<html>`, not of a `data-theme` scope around the trigger. Set the theme on `<html>`, or give the menu its own scope: `<ContextMenuContent data-theme="dark">` (the prop is passed through).

## Accessibility

- The content is `role="menu"`; items are `menuitem`, `menuitemcheckbox` (with `aria-checked`) or `menuitemradio`, separators `separator`, groups `group`.
- It opens on the `contextmenu` event (usually a right-click) and on a 700ms long press with a touch or a pen, at the pointer. The trigger has no role and adds no keyboard access (by default it is a `<span>`, which is not focusable), so keyboard and screen-reader users may never find the menu. Offer every action somewhere else too.
- To keep the menu open after a selection, call `event.preventDefault()` in the item's `onSelect`.
- The menu is modal by default (Radix `modal`): while it is open, focus stays in it, the rest of the page is hidden from assistive technology and ignores the pointer, and the page doesn't scroll. `modal={false}` turns this off.
- When the menu closes, focus goes back to the element that had it before the menu opened (not after a click outside a `modal={false}` menu).
- There are no built-in strings. A `ContextMenuShortcut` is a `<kbd>` with `aria-keyshortcuts`; it only shows the shortcut.

### Keyboard

In the open menu the keys are those of [DropdownMenu](?path=/docs/components-dropdownmenu--docs) (Radix Menu); disabled items are skipped:

| Key | Action |
| --- | --- |
| Shift + F10, the Menu key | with focus on an element inside the trigger: open the menu on its first item. This is browser behaviour: the browser turns these keys into a `contextmenu` event, and not every browser or OS does. The default `<span>` trigger can't take focus |
| ArrowDown / ArrowUp | move to the next / previous item; no wrapping unless `loop` is set on the content. After a right-click or a long press focus is on the menu itself: ArrowDown moves to the first item, ArrowUp to the last |
| Home / End, PageUp / PageDown | move to the first / last item |
| a character | move to the next item whose text starts with the typed characters (typeahead); once typing has started, Space is part of the search |
| Enter, Space | select the item and close the menu (a checkbox item toggles, a radio item is picked); on a sub trigger, open the submenu on its first item |
| ArrowRight (ArrowLeft in right-to-left text) | on a sub trigger: open the submenu and focus its first item |
| ArrowLeft (ArrowRight in right-to-left text) | in a submenu: close it and focus its trigger |
| Escape | close the menu, submenus included |
| Tab, Shift + Tab | do nothing while the menu is open |

### Deviations from the Figma kit

The full table is in the package README.

| Figma | Library | WCAG |
| --- | --- | --- |
| Group labels, shortcuts and submenu value hints in Black/40%: 2.85:1 on white, 3.41:1 on #333 | `text-secondary`: Black/60% in light mode (5.74:1 on `background-1`), White/70% in dark mode (7.08:1 on #333, at least 4.76:1 on the lightest popover surface) | 1.4.3 |
| Submenu chevron in Black/20%: 1.6:1 | `text-secondary`, as the Select chevron: Black/60% in light mode (at least 5.5:1, on the highlighted item too), White/70% in dark mode (at least 4.82:1) | 1.4.11 |
| Destructive item (the red "Delete" row; 5.2): red text and icon | `variant="destructive"`: `red-text` (#D42020: 5.21:1 on the popover, 4.77:1 highlighted); in dark mode `red-text` mixed with 40% white (#FFB3B3: 6.21:1, 4.59:1 highlighted), as #FF8080 is 4.36:1 and 3.22:1 there | 1.4.3 |

The Black/4% item highlight (1.1:1) keeps the Figma value with the default contrast: the README lists it as a known gap. With more contrast (`prefers-contrast: more` or `data-contrast="more"`; see [Contrast](?path=/docs/guides-contrast--docs)) the highlighted item also gets a 2px `black-80` ring.

## Localization and RTL

- The menu renders no text of its own: labels and shortcuts are yours to translate.
- The content takes `dir` from `SnowUIProvider`; without a provider (or a Radix `DirectionProvider`) it is `ltr`, whatever `<html dir>` says.
- In right-to-left text the check marks (at the left end), `inset` padding and shortcuts swap sides, the submenu arrow points left, and ArrowLeft opens a submenu.

## Composition (asChild)

`ContextMenuTrigger` and the items take `asChild` (Radix). On the trigger it renders your element instead of the `<span>`, e.g. a card or a list row:

```tsx
<ContextMenu>
  <ContextMenuTrigger asChild>
    <div className="rounded-16 bg-surface-1 p-6">…</div>
  </ContextMenuTrigger>
  <ContextMenuContent>…</ContextMenuContent>
</ContextMenu>
```

Checkbox items take `checked` / `onCheckedChange` and a radio group `value` / `onValueChange`. The root takes `open` / `onOpenChange` (there is no `defaultOpen`). The menu is placed at the point of the last right-click or long press, so `open` set before the user has opened it puts the menu at the top-left corner of the viewport (Radix warns in development).

## Do and don't

<DoDont>
<Do>

- Put the same actions in a visible place too: a toolbar, buttons, or a DropdownMenu on a "more" button.
- Keep the menu short, with the most used action first.
- Give the trigger a clear area: size it with a class, or render your element with `asChild`.
- Group items with `ContextMenuLabel` and separators.

</Do>
<Dont>

- Don't make a context menu the only way to reach an action.
- Don't put fields or long text in it: use a Popover.
- Don't nest submenus more than one level deep.

</Dont>
</DoDont>

## Props

The parts are the [Radix Context Menu](https://www.radix-ui.com/primitives/docs/components/context-menu#api-reference) parts with the Figma Popover styles; `ContextMenuShortcut` is a [KBD](?path=/docs/components-text-kbd--docs). They take the props below, `className` (merged with the part's classes) and the attributes of the element they render.

The root: it holds the open state and renders nothing. `open` / `onOpenChange` control it (there is no `defaultOpen`); `modal` is `true` by default; `dir` overrides the direction from `SnowUIProvider`.
