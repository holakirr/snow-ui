Textarea is a multi-line text field. It is the Figma "Textarea": the Input field (padding, radius, stroke, text style and states) on a native `<textarea>`, with the Figma character counter (`showCount`). `readOnly` gives the Figma "Static" state.

```tsx
import { Label, Textarea } from '@holakirr/snow-ui'

<Label htmlFor="message">Message</Label>
<Textarea id="message" rows={4} value={message} onChange={(event) => setMessage(event.target.value)} />
```

<Primary />

## When to use

- Free text that can run over several lines: a message, a description, a note.

## When not to use

- A single line: use [Input](?path=/docs/components-input-input--docs), which also has a built-in `title`.
- A compact field in a toolbar: [InputSmall](?path=/docs/components-input-input-small--docs).

## Anatomy

1. **Textarea**: the native `<textarea>`. Every prop except `showCount` and `containerClassName` goes to it; `className` merges with its classes. It is full width and at least 44px (one row) high; `rows` or a height class sets the height. It has 12 / 16px padding, a 16px radius, Surface/1 with a 0.5px Black/20% inside stroke, 14/20 text and a Black/20% placeholder.
2. **Counter** (`showCount`): "12/200" against the `maxLength` (just "12" without one), 12/16, 4px above the bottom edge and 20px from the end, next to the resize handle in the corner. The textarea's bottom padding is then 20px, so the text stops above the counter (one row is 52px; the Figma 44px frame lets the last line run under it). The textarea and the counter are then in a `<div data-slot="textarea-field">`: size the field with `containerClassName` on it (a width on the textarea would leave the counter at the div's edge). Switching `showCount` on or off remounts the textarea (an uncontrolled value is lost).

There is no `title` prop: label it with a [Label](?path=/docs/components-label--docs), a `FormLabel` or `aria-label`.

## States

- **Hover:** the stroke turns Black/40%.
- **Focus:** the Figma "Focus" state on any focus, by mouse or keyboard: a Black/40% stroke and the 4px Focus ring. Text fields don't get the `focus-ring` outline. With more contrast the focus stroke is 2px (Black/80%, the stroke colour when read-only): the Figma 0.5px Black/40% stroke is 2.85:1 on the fill.
- **Static** (`readOnly`): the stroke stays Black/20% on hover and focus; the 4px Focus ring still shows while it has focus.
- **Disabled** (`disabled`): Black/4% fill, no stroke, Black/20% text and a not-allowed cursor. The Figma set has no Disabled state, so this look is the library's own, shared with Input.
- **Invalid** (`aria-invalid`, which `FormControl` of [Form](?path=/docs/components-form--docs) sets): the Input's 1px Secondary/Red stroke, also on hover and focus (no Figma state).

## Counter

<Canvas of={TextareaStories.WithCount} />

With `showCount` the counter shows how many characters are used, against the `maxLength` if there is one (the browser stops typing at the limit), as the Figma Textarea does. It is opt-in in 5.x, because it wraps the textarea in a `<div>`: layout classes on `className` (a width, `flex-1`, a grid span) and `peer-*` siblings of the textarea would no longer apply. It counts `value` when you control the field, and follows typing, a new `defaultValue` of an unedited field, a value the browser restores and a reset of the form otherwise; control the field when you set its value from code (e.g. react-hook-form's `setValue` on a registered field).

## Accessibility

- It renders a native `<textarea>`.
- Give it an accessible name: a `Label` with `htmlFor` and the same `id`, a `FormLabel` inside a [Form](?path=/docs/components-form--docs) item, or `aria-label` (as the stories do). A placeholder is not a label.
- `disabled` removes the field from the tab order; a `readOnly` field stays focusable and its text can be selected and copied.
- The counter is `aria-hidden`. The field is described instead by a hidden "12 of 200 characters" (`aria-describedby`, after any description of its own, e.g. from `FormControl`): screen readers read it with the field when it gets focus, and a live region doesn't announce every keystroke.

Deviation from the Figma kit: the counter is `text-secondary` (5.74:1) instead of Black/20% (1.6:1), as the Search shortcut hint. Known gaps with the default contrast, which keeps the Figma values: the 0.5px Black/20% stroke (1.6:1) and the Black/20% placeholder (it is never the field's only label). With more contrast (`prefers-contrast: more` or `data-contrast="more"`; see [Contrast](?path=/docs/guides-contrast--docs)) the stroke is a 1px `control-border` (Black/50%, at least 3.79:1) and the placeholder Black/60% (at least 5.25:1), White/50% and White/75% in dark mode.

### Keyboard

Keyboard behaviour is the browser's:

| Key | Action |
| --- | --- |
| Tab | move focus to the textarea, and on to the next control: it doesn't type a tab character |
| Enter | add a line; it doesn't submit the form |

## Localization and RTL

- The only built-in string is the counter's description, `messages.textarea.count`: "12 of 200 characters", or "12 characters" without a `maxLength`.
- The counter goes to the end (the left in right-to-left text), with the resize handle; its digits read left to right.
- The text follows the direction of the page or of a `dir` attribute on the field.

## Controlled and uncontrolled

Textarea is a native field: pass `value` with `onChange` to control it, or `defaultValue` to leave the value to the browser.

## Do and don't

<DoDont>
<Do>

- Label every textarea with a visible `Label` or `FormLabel`.
- Set `rows` to the length of text you expect.
- Use `readOnly` for text that can be copied but not changed.

</Do>
<Dont>

- Don't use the placeholder as the only label or for instructions: put them in a `FormDescription`.
- Don't use a textarea for a single-line value: use Input.
- Don't use `disabled` for text the user needs to read or copy.

</Dont>
</DoDont>
