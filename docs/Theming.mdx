# Theming

The styles implement the SnowUI Figma tokens — the SnowUI-Light and SnowUI-Dark modes of the kit's variables, its text styles and its effect styles — as Tailwind CSS v4 theme variables. The source of truth is the [W3C Design Tokens (DTCG)](https://www.designtokens.org/) files in [`packages/ui/tokens`](https://github.com/holakirr/snow-ui/tree/main/packages/ui/tokens); `bun run tokens` generates the CSS from them. The [Foundations](?path=/story/foundations--colors) pages list every token with its Figma name and both mode values.

## Tokens

Every token is a CSS variable (`var(--color-black-10)`) and, through Tailwind, a utility (`bg-black-10`, `text-14`, `rounded-12`).

| Group | Utilities | Notes |
| --- | --- | --- |
| Colours | `primary`, `black`, `white` and their Figma alpha steps (`black-80`, `black-40`, `black-20`, `black-10`, `black-4`, same for `white`), `background-1…3`, `surface-1…3`, `color-1`, `color-2`, `static-white`, `static-black`, the secondary colours (`purple`, `indigo`, `blue`, `cyan`, `mint`, `green`, `yellow`, `orange`, `red`) | `primary` is black in light mode and indigo in dark mode; `black` and `white` swap. `static-*` never change. |
| Accessible text | `text-secondary`, `indigo-text`, `red-text` | Library additions for 4.5:1 text where Figma's Black/40% or indigo fall short. |
| Form controls | `control-border`, `control-border-strong`, `placeholder` | Library additions: the Figma Black/20% and 40% by default, WCAG AA with more contrast (see [Contrast](?path=/docs/guides-contrast--docs)). |
| Typography | `text-12` … `text-64` | The Figma text styles (size and line height). Inter with `font-feature-settings: "ss01" 1, "cv01" 1` and `font-optical-sizing: none`. |
| Radius | `rounded-4` … `rounded-80` | The Figma corner radius scale. |
| Spacing | Tailwind's (`p-1` = 4px, `gap-3` = 12px) | The Figma spacing values are multiples of 4px. |
| Effects | `shadow-1`, `shadow-2`, `shadow-glow`, `shadow-glass-1`, `shadow-glass-2`, `inset-shadow-inner`, `ring-focus` / `shadow-focus`, `backdrop-blur-bg-40`, `backdrop-blur-bg-100` | The Figma effect styles. |
| Glass | `glass` (= `glass-2`), `glass-1`, `glass-2` | Approximations of Figma's Glass effects: a fill, a background blur and the effect's shadow. |

In dark mode `black-10` and `black-4` use the kit's stronger alphas (15% and 10%). Tailwind's opacity modifiers (`black/10`) keep one alpha in both modes, so prefer the tokens.

Three utilities and a base rule come with the theme:

- `focus-ring`: the keyboard focus indicator of every control. On `:focus-visible` it draws the Figma "Focus" ring (`ring-4 ring-focus`) plus a 2px `black-80` outline offset by 2px. Use it on your own focusable elements: `<button className="focus-ring">`.
- `hit-area`: an invisible pointer hit area of at least 24×24px centred on a smaller control (WCAG 2.5.8 Target Size), drawn by its `::after`. The element needs a position: `<button className="relative hit-area">`. Bare icon buttons, `Switch`, the `Slider` thumb, sortable `Table` headers, line tabs and the `Search` clear button have one.
- Cursors: buttons and ARIA controls (`option`, `menuitem`, `tab`, `radio`, `checkbox`, `switch`, `label[for]`…) get the pointer cursor, which Tailwind v4's preflight no longer sets, and disabled elements the not-allowed cursor. `cursor-*` utilities override it.

Old token names (`brand`, `bg1`…`bg5`, `brand-hover` and the shadcn-style `background`, `foreground`, `muted`, `accent`, `destructive`, `input`, `ring`…) still work as deprecated aliases.

## Dark mode

The theme is light by default. It is dark:

- with `data-theme="dark"` or the `dark` class on `<html>` (the class next-themes and shadcn/ui set: `<ThemeProvider attribute="class">`), or
- with the OS dark preference, when `<html>` sets no mode: `data-theme="light"` or the `light` class pins the light theme.

`color-scheme` follows, so native controls and scrollbars match. Components need no props for it: their colours are tokens.

## Scoped themes

`data-theme` (or the `light` / `dark` class) works on any element: the tokens of an element come from its nearest scope ancestor, so a subtree can use the other mode, and `data-theme="light"` inside a dark subtree switches back.

```tsx
<html data-theme="light">
  …
  <aside data-theme="dark" className="bg-background-1 text-black">
    {/* dark tokens: background-1 is #333, black is white */}
    <div data-theme="light">{/* light again */}</div>
  </aside>
</html>
```

- A scope sets the tokens and `color-scheme`, not a background or text colour: paint it, e.g. `bg-background-1 text-black`.
- `dark:` utilities follow the same scopes, with one limit: a dark scope inside a light scope inside a dark scope gets the dark tokens but not `dark:` utilities. Prefer the tokens, which switch at any depth.
- **Portals:** the content of `Dialog`, `AlertDialog`, `Sheet`, `Popover`, `DropdownMenu`, `ContextMenu`, `Tooltip`, `Select`, `CommandPalette`, the lists of `Combobox` and `MultiSelect` and the calendars of `DatePicker` and `DateRangePicker` renders at the end of `<body>`, outside your scope. With a plain `data-theme` attribute it takes the theme of `<html>`. Make the scope a `ThemeScope` instead: it renders the element with `data-theme` (or sets it on its child with `asChild`) and passes the theme to the overlays opened inside it, which get it as their own `data-theme`:

  ```tsx
  import { ThemeScope } from '@holakirr/snow-ui'

  <ThemeScope theme="dark" className="bg-background-1 text-black">
    <Select>…</Select> {/* its listbox is dark too */}
  </ThemeScope>
  ```

  `SnowUIProvider`'s `theme` does the same for the overlays without rendering an element, and a `data-theme` on a `*Content` component still wins. Toasts render inside `<Toaster />`, so they take the theme of wherever you place it.

In this Storybook, the theme toolbar switches every story; stories named "Dark" pin the dark theme.

## Contrast

The form controls keep the Figma kit's Black/20% rings, strokes and placeholders (1.6:1) by default and meet WCAG AA with more contrast: with the OS preference `prefers-contrast: more`, or inside `data-contrast="more"` on any element (`data-contrast="standard"` switches back). Contrast and theme scopes combine at any depth. The [Contrast](?path=/docs/guides-contrast--docs) guide lists the tokens, every measured ratio and how the scopes work.

## Motion

With the OS setting `prefers-reduced-motion: reduce` (WCAG 2.3.3), the overlays — Dialog and Sheet backdrops, Sheet, Popover, menus, Select, Tooltip, Toast, CommandPalette — fade instead of sliding or zooming, with the same timing, and the Accordion opens and closes at once: `theme.css` points the `--animate-*` tokens at the fades (see [Foundations › Motion](?path=/story/foundations--motion)). The components' own movements use `motion-reduce:` utilities: a pressed Button doesn't shrink, the Switch thumb and the Accordion chevron jump, a Dialog or AlertDialog only fades, the Skeleton stops pulsing and the Sidebar collapses and expands at once (the Spinner and Progress pulse instead of turning or sliding). State changes stay visible. Use the `animate-*` tokens and `motion-reduce:` in your own components the same way.

## Tailwind CSS v4 projects: `theme.css`

`theme.css` is the theme without Tailwind itself: the tokens as theme variables, the theme and contrast scopes, the `dark` and `contrast-more` variants, the `glass*`, `focus-ring` and `hit-area` utilities, the base rules and react-day-picker's stylesheet (for `Calendar`). `index.css` is the same compiled with Tailwind, for projects without it.

```css
@import "tailwindcss";
@import "@holakirr/snow-ui/theme.css";
```

It adds the package's built components to Tailwind's sources itself (`@source`, relative to its own file); with 5.0 or older, add `@source "../node_modules/@holakirr/snow-ui/dist";` yourself.

What it changes in your Tailwind setup:

- `dark:` follows the scoped themes (`data-theme` or the `light` / `dark` classes, then the OS preference) instead of only `prefers-color-scheme`, and `contrast-more:` the contrast scopes (`data-contrast`, then `prefers-contrast`) instead of only the OS preference.
- With `prefers-reduced-motion: reduce`, the theme's `--animate-slide-*` and `--animate-zoom-*` tokens fade and `--animate-accordion-*` don't animate.
- It overrides Tailwind's `--font-sans` (Inter), `--color-black` and `--color-white` (which swap in dark mode).
- It adds the kit's scales next to Tailwind's: `text-12`…, `rounded-4`…, the colours above.

**Cascade layers.** Both stylesheets keep every rule in Tailwind's layers (`theme`, `base`, `components`, `utilities`; react-day-picker's stylesheet is in `components`). Your unlayered CSS overrides them whatever the load order or specificity, and your utilities override the base and component rules.

## Changing a token

Redeclare its variable in your own (unlayered) CSS, for each scope it should apply to:

```css
:root,
[data-theme="light"],
.light {
  --color-primary: #0f62fe;
}

[data-theme="dark"],
.dark {
  --color-primary: #78a9ff;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme], .light, .dark) {
    --color-primary: #78a9ff;
  }
}
```

Check the contrast of text and controls on the new colour: the accessibility deviations of the components (see each component's page) were measured with the kit's values.

Styling a single component: pass `className`. It is merged with the component's classes by a token-aware `twMerge`, so `className="rounded-8"` replaces the component's radius instead of fighting it in the stylesheet.

## Fonts

`fonts.css` self-hosts Inter 4.1 with the `ss01` / `cv01` features (see [Getting started](?path=/docs/guides-getting-started--docs#add-the-font-optional)). The stylesheets only set `font-family: Inter, sans-serif`, the feature settings and `font-optical-sizing: none`: the kit uses the "Inter" family (text optical size) at every size, not "Inter Display". If you load Inter yourself, use a build with those features. The italic faces are opt-in (`fonts-italic.css`), since the design has no italic text.
