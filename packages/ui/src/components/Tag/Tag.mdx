Tag is a short label: a category, a keyword, an applied filter. It is the Figma "Tag" set (State × Type): three states, a rounded tag or one with an arrow tip, an optional dot or icon before the label and an optional remove button after it.

```tsx
import { Tag } from '@holakirr/snow-ui'

<Tag label="Design" dot onRemove={() => removeFilter('design')} />
```

<Primary />

## When to use

- Categories or keywords on an item.
- Applied filters or selected values that the user can remove (`onRemove`).
- A selected tag among others (`state="active"`).

## When not to use

- A count or a "new" marker: use [Badge](?path=/docs/components-badge--docs).
- An action: use [Button](?path=/docs/components-button--docs). The tag itself isn't focusable or clickable; only its remove button is.
- Picking one or several options: [ToggleGroup](?path=/docs/components-input-togglegroup--docs) or [Checkbox](?path=/docs/components-input-checkbox--docs).
- Navigation: use [Link](?path=/docs/components-link--docs).

## Anatomy

1. **Container**: a 20px-high `<div>` with an 8px radius and a fill set by `state`. It has no role of its own.
2. **Start content** (optional, rounded tags only): `startContent` (e.g. a 12px icon) or, with `dot`, the Figma "Dot" icon. `startContent` wins over `dot`.
3. **Label** (`label`, required): 12/16 text.
4. **Remove button** (`onRemove`, optional, rounded tags only): a 12px close icon in a `<button>`.
5. **Arrow tip** (`shape`, arrow shapes only): an SVG in the tag's fill. The arrow shapes have no start content and no remove button.

`state` is the Figma "State"; Hover is the pointer state of `default`.

| `state` | Look | Use for |
| --- | --- | --- |
| `default` (default) | Black/4% fill; Black/10% and a pointer cursor on hover | removable tags and filters |
| `active` | `indigo-text` label and icons on a 10% indigo fill; a pointer cursor on hover | the selected tag |
| `static` | Black/4% fill, no hover | read-only labels |

`shape` is the Figma "Type": the rounded tag, or a tag with an arrow tip (the Figma "Left arrow" tag, and its mirror).

| `shape` | Tip |
| --- | --- |
| `default` (default) | none |
| `arrow-start` | on the start side, pointing to the start (flips in right-to-left text) |
| `arrow-end` | on the end side, pointing to the end (flips) |
| `arrow-left` | on the left, in both directions |
| `arrow-right` | on the right, in both directions |

## States

- **Hover:** `default` tags go from Black/4% to Black/10%. `active` tags keep their fill. `static` tags don't react.
- **Active:** `state="active"` is the selected state; it is a look only. Tell assistive technology yourself if selection matters (e.g. in a visible "Selected" heading, or `aria-pressed` on a control that toggles it).
- **Remove button:** the close icon is at 80% opacity, 100% on hover and keyboard focus, where it also gets the `focus-ring`.

## Accessibility

- The tag is a `<div>` with no role, so it is valid on its own. For a list of tags, render them in a `role="list"` container and pass `role="listitem"` to each, or wrap each in an `<li>` of a `<ul>`.
- The remove button is a native `<button type="button">`. Its accessible name, also shown as a `title` tooltip, is "Remove tag" followed by the label; `removeLabel` replaces it.
- The close icon and the dot are `aria-hidden`. Icons from `@holakirr/snow-ui-icons` in `startContent` are too, unless they get an `alt`.
- After a removal, move focus somewhere sensible (the next tag's remove button, or the field that adds tags): the focused button is gone.

### Keyboard

The tag itself is not focusable; only its remove button is a tab stop. Backspace and Delete don't remove a tag:

| Key | Action |
| --- | --- |
| Tab | move focus to the remove button (a `default`-shape tag with `onRemove`) |
| Enter, Space | call `onRemove` |

### Deviations from the Figma kit

The full table is in the package README.

| Figma | Library | WCAG |
| --- | --- | --- |
| Close icon at 40% layer opacity: 2.85:1 | 80%: at least 3.46:1 on every tag, the active indigo one included (60% would be 2.43:1 there); 100% on hover and keyboard focus | 1.4.11 |
| Close button: a 12px icon | the same icon with a 24×24px hit area, so the tag stays 20px high | 2.5.8 |
| Active label Secondary/Indigo `#ADADFB`: 2.07:1 on white | `indigo-text`: `#5B5BD6` in light mode (5.04:1 on the active tint), `#ADADFB` in dark mode (6.11:1); the fill keeps the Figma indigo | 1.4.3 |
| The "Focus" effect: a 4px Black/4% ring (1.1:1) | `focus-ring` on the remove button: the ring plus a 2px `black-80` outline offset by 2px (12.6:1 light, 8.7:1 dark) | 2.4.7, 1.4.11 |

## Localization and RTL

- The remove button's name is `messages.tag.remove(label)`, `Remove tag ${label}` in English. `removeLabel` overrides the provider.
- `startContent` and the remove button follow the text direction: in right-to-left text the start content is on the right and the remove button on the left. The deprecated `leftContent` is an alias of `startContent`.
- `arrow-start` and `arrow-end` flip with the direction; `arrow-left` and `arrow-right` keep pointing left and right.

<Canvas of={TagStories.RTL} />

The deprecated `onClose` is an alias of `onRemove`. Both `leftContent` and `onClose` log a one-time development warning and will be removed in the next major version.

## Do and don't

<DoDont>
<Do>

- Keep labels to a word or two.
- Use `onRemove` for tags the user added, and move focus after a removal.
- Use `static` for tags that only inform.
- Put a list of tags in a list (`role="list"` and `role="listitem"`, or `<ul>` and `<li>`).

</Do>
<Dont>

- Don't add an `onClick` to a tag to make it act: it isn't focusable. Use a [Button](?path=/docs/components-button--docs) or a [Toggle](?path=/docs/components-input-toggle--docs).
- Don't rely on `active` alone to show selection to screen reader users.
- Don't combine an arrow shape with `dot`, `startContent` or `onRemove`: they are ignored.
- Don't use the deprecated `leftContent` or `onClose` in new code.

</Dont>
</DoDont>
