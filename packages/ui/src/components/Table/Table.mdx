Table shows records in rows and columns. It is a styled native `<table>` in the Figma Table style: 12/16 text, 40px rows, a Black/20% line under the header, Black/4% lines between rows and a rounded Black/4% highlight on hovered and selected rows. `TableHead` can be a sort button, `TableToolbar` is the function bar above the table, and `TableCell reveal` shows a row's checkbox and actions on hover. Table holds no data or state: pair it with a library such as TanStack Table for sorting, filtering, selection and pages, as the stories do.

```tsx
import {
  Table,
  TableBody,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from '@holakirr/snow-ui'

<Table>
  <TableHeader>
    <TableRow>
      <TableHead>Order ID</TableHead>
      <TableHead>Status</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>#CM9801</TableCell>
      <TableCell>In Progress</TableCell>
    </TableRow>
  </TableBody>
</Table>
```

## When to use

- Records that share fields and are compared across rows: orders, tasks, users.
- Data the user sorts, filters, selects or pages through.

## When not to use

- A list of people or notifications with one or two lines each: use [ListItem](?path=/docs/components-listitem--docs).
- Page layout: use CSS grid or flex, never a table.
- A few key figures: use stat tiles ([Card](?path=/docs/components-card--docs) blocks).

## Anatomy

1. **Scroll container**: a `<div>` with `overflow: auto` around the table, so a wide table scrolls instead of overflowing.
2. **Table** (`Table`): the `<table>`, full width, 12/16 `text-black`, in the separate border model (cells can't have rounded corners in the collapsed one), so the lines are drawn on the cells.
3. **Caption** (`TableCaption`, optional): 14/20 semibold, start-aligned, above the table with 4px between them.
4. **Header** (`TableHeader`, `TableRow`, `TableHead`): `<thead>` and `<th>` cells, `text-secondary`, with a Black/20% line below.
5. **Body** (`TableBody`, `TableRow`, `TableCell`): `<tbody>` and `<td>` cells with a Black/4% line below each.
6. **Footer** (`TableFooter`, optional): `<tfoot>`, its cells with a Black/20% line above and none below.
7. **Function bar** (`TableToolbar`, optional, outside the `Table`): a `<div>` above the table, a Background/2 strip with radius 12, padded 8px and at least 44px high, its children in a row 16px apart. The kit puts borderless icon buttons (add, filter, sort) at the start and a [Search](?path=/docs/components-search--docs) at the end (`ms-auto`).

Header and body cells are 40px high, padded 8px top and bottom and 12px at the sides, start-aligned and vertically centred. A cell that holds a `role="checkbox"` element has no end padding.

## Sorting

`sortDirection` makes a `TableHead` a sort button with a 16px sort icon, and sets `aria-sort` on the `<th>`. `onSort` is called on click.

| `sortDirection` | Icon | Label | `aria-sort` |
| --- | --- | --- | --- |
| `undefined` (default) | none, plain header | `text-secondary` | not set |
| `false` | up and down arrows | `text-secondary`, black on hover | `none` |
| `'asc'` | up arrow | black | `ascending` |
| `'desc'` | down arrow | black | `descending` |

With TanStack Table:

```tsx
<TableHead
  sortDirection={column.getCanSort() ? column.getIsSorted() : undefined}
  onSort={column.getToggleSortingHandler()}
>
  {header}
</TableHead>
```

## States

- **Row hover:** the row's cells get a Black/4% fill, rounded 12px at the first and last cell. Header rows don't react, and neither does a header cell without sorting: the kit's Table Title darkens on hover, but a header that does nothing shouldn't look like a control. A sortable header does (below).
- **Selected row:** `data-state="selected"` on a `TableRow` gives the same highlight. Selection itself is yours (the stories use checkboxes and TanStack's row selection).
- **Revealed controls:** the elements of a `TableCell` with `reveal` are transparent until their row is hovered or selected, or while they hold the keyboard focus, a checked (or mixed) checkbox, the Checkbox component or a native `<input type="checkbox">`, or an open menu (`aria-expanded="true"`). On devices without hover (touch screens) they always show.
- **Sort button:** hover turns the label black; keyboard focus shows the `focus-ring`.
- **Empty:** Table has no empty state of its own; render a row with one cell spanning every column, as the NoResults story does.

## Accessibility

- The parts are native table elements, so screen readers announce rows, columns and headers. `TableCell` also sets `role="cell"`.
- A sortable header is a `<button type="button">` inside the `<th>`. The `<th>` carries `aria-sort`; the sort icon is decorative.
- Name the table: a `TableCaption`, or `aria-label` / `aria-labelledby` on `Table` (they go on the `<table>`).
- Selection checkboxes need a name per row (the stories use "Select #CM9801" and "Select all"). The select-all checkbox reports `aria-checked="mixed"` when only some rows are selected (the Table A tests check it).
- Controls that appear on hover must also appear on keyboard focus: `reveal` shows them while they have focus, and keeps them in the tab order and the accessibility tree (they are transparent, not hidden), so they have names like any control.
- `TableToolbar` is a plain `<div>`: give its buttons names (the story's "Add order", "Filter", "Sort"). Add `role="toolbar"` only if you also move between its controls with the arrow keys.
- Hover and the selected highlight are a fill only; say which rows are selected with the checkboxes' state, not the fill.

### Keyboard

The table itself isn't focusable and has no arrow-key navigation; its sort buttons and whatever you put in the cells are ordinary tab stops:

| Key | Action |
| --- | --- |
| Tab / Shift + Tab | move to the next / previous control: sort buttons, then the controls in the cells, row by row |
| Enter, Space | on a sort button: call `onSort`, which changes the sort |
| Space | on a selection [Checkbox](?path=/docs/components-input-checkbox--docs): toggle the row (the Table A tests check it) |

### Deviations from the Figma kit

The full table is in the package README.

| Figma | Library | WCAG |
| --- | --- | --- |
| Header text in Black/40%: 2.85:1 on white, 3.41:1 on #333 | `text-secondary`: Black/60% in light mode (5.74:1 on `background-1`), White/70% in dark mode (7.08:1 on #333) | 1.4.3 |
| The "Focus" effect: a 4px Black/4% ring (1.1:1) | `focus-ring` on the sort buttons: the ring plus a 2px `black-80` outline offset by 2px (12.6:1 light, 8.7:1 dark) | 2.4.7, 1.4.11 |

The stories' status cells colour only the dot: the Secondary colours are 1.7–2.4:1 as text, so the text stays black and carries the meaning.

## Localization and RTL

- Table renders no built-in strings: headers, captions and the names of your checkboxes and actions are yours to translate.
- The cells are start-aligned and the row highlight rounds the start and end cells (`rounded-s-12`, `rounded-e-12`), so both follow the text direction.

## Do and don't

<DoDont>
<Do>

- Name the table with a caption or `aria-label`.
- Pass `sortDirection={false}` for sortable columns that aren't sorted, and `undefined` for the others.
- Mark selected rows with `data-state="selected"` and a checked checkbox.
- Show hover-only actions on keyboard focus too: use `reveal` on their cells.

</Do>
<Dont>

- Don't use a table for layout.
- Don't colour status text with the Secondary colours: colour a dot next to it.
- Don't make whole rows clickable without a focusable control in them.

</Dont>
</DoDont>
