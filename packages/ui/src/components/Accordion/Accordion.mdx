Accordion is a stack of sections whose content opens and closes under a heading. It is built on Radix Accordion: `Accordion` is the stack, `AccordionItem` a section, `AccordionTrigger` its heading button and `AccordionContent` its content. `type="single"` keeps one section open at a time; `type="multiple"` lets any number stay open.

```tsx
import {
  Accordion,
  AccordionContent,
  AccordionItem,
  AccordionTrigger,
} from '@holakirr/snow-ui'

<Accordion type="single" collapsible>
  <AccordionItem value="shipping">
    <AccordionTrigger>Shipping</AccordionTrigger>
    <AccordionContent>Orders ship within two days.</AccordionContent>
  </AccordionItem>
</Accordion>
```

## When to use

- Long pages of sections that users scan by heading and open as needed: FAQs, settings groups, details.
- Secondary content that would crowd the page if it were always visible.

## When not to use

- Switching between views of the same area: use [Tabs](?path=/docs/components-tabs--docs).
- Navigation with nested items: use the [Sidebar](?path=/docs/components-sidebar--docs) menu parts (`SidebarMenuSub`).
- Content most users need: show it, don't hide it behind a trigger.
- A panel over the page: use [Sheet](?path=/docs/components-sheet--docs) or [Popover](?path=/docs/components-popover--docs).

## Anatomy

1. **Stack** (`Accordion`): a column of items 4px apart, `text-black`. `type` is required.
2. **Item** (`AccordionItem`): one section, identified by its `value`. It has no style of its own.
3. **Heading and trigger** (`AccordionTrigger`): an `<h3>` holding a full-width `<button>`: the `children` in 16/24 text, then an arrow that points to the end side and turns down when the item is open. The button has a 12px radius and 8 / 16px padding, with 8px between the text and the arrow.
4. **Content** (`AccordionContent`): padded 16px, 4px at the top. It slides open and closed in 0.3s, and isn't rendered while closed.

## Variants

| `type` | Behaviour | Extra props |
| --- | --- | --- |
| `single` | opening an item closes the open one | `collapsible`: the open item can be closed too; without it one item always stays open once opened |
| `multiple` | items open and close independently | none |

## States

- **Hover and keyboard focus:** the trigger gets a Black/4% fill and its arrow turns from `text-secondary` to black, as the kit's small chevrons (Black/20% at rest in the kit, 1.6:1, so `text-secondary` here); keyboard focus adds the `focus-ring`.
- **Open:** the trigger has `data-state="open"` and `aria-expanded="true"`, and the arrow turns down.
- **Disabled:** `disabled` on `Accordion` or on an `AccordionItem` disables the triggers; there is no disabled style.
- In a `single` accordion without `collapsible`, the open item's trigger has `aria-disabled` because it can't close it.

## Accessibility

- Each trigger is a `<button>` inside an `<h3>` (Radix `Accordion.Header`), with `aria-expanded` and `aria-controls`. The heading level is fixed at 3: check that it fits your page's outline.
- An open item's content is a `role="region"` labelled by its trigger.
- The trigger's name is its text. The arrow icon is decorative.

### Keyboard

Every trigger is a tab stop (Radix Accordion):

| Key | Action |
| --- | --- |
| Tab / Shift + Tab | move to the next / previous trigger, or to the focusable elements in an open item's content |
| Enter, Space | open or close the focused item; in a `single` accordion without `collapsible`, the open item's trigger does nothing |
| ArrowDown / ArrowUp | move focus to the next / previous trigger, wrapping around at the ends; disabled triggers are skipped |
| Home / End | move focus to the first / last trigger |
| ArrowRight / ArrowLeft | with `orientation="horizontal"`, instead of ArrowDown / ArrowUp: move focus to the next / previous trigger. In right-to-left text ArrowLeft moves to the next trigger |

### Deviations from the Figma kit

The full table is in the package README.

| Figma | Library | WCAG |
| --- | --- | --- |
| The "Focus" effect: a 4px Black/4% ring (1.1:1) | `focus-ring`: the ring plus a 2px `black-80` outline offset by 2px (12.6:1 light, 8.7:1 dark), over the Black/4% fill | 2.4.7, 1.4.11 |

## Localization and RTL

- Accordion renders no built-in strings.
- In right-to-left text the arrow is mirrored to point to the end side (left), and still turns down when open.
- With `orientation="horizontal"`, the arrow keys follow the provider's `dir`: in right-to-left text ArrowLeft moves forward.

## Controlled and uncontrolled

`defaultValue` sets the open items once; `value` and `onValueChange` control them. With `type="single"` the value is a string (an item's `value`, or `''` for none); with `type="multiple"` it is an array of strings.

```tsx
const [open, setOpen] = useState<string[]>(['shipping'])

<Accordion type="multiple" value={open} onValueChange={setOpen}>
  …
</Accordion>
```

## Do and don't

<DoDont>
<Do>

- Write triggers as short, scannable headings.
- Use `collapsible` with `type="single"`, so users can close what they opened.
- Keep each item's content short; split long content into more items.

</Do>
<Dont>

- Don't put interactive controls inside `AccordionTrigger`: it is a `<button>`.
- Don't nest accordions.
- Don't hide the only copy of required information or of a form's errors in a closed item.

</Dont>
</DoDont>

## Props

The parts are the [Radix Accordion](https://www.radix-ui.com/primitives/docs/components/accordion#api-reference) parts with the library's styles: they take the Radix props below, `className` (merged with the part's classes) and the attributes of the element they render.

### Accordion

The root, a `<div>`: `type` (required) picks `single` or `multiple`; the open items are controlled with `value` and `onValueChange`, or uncontrolled with `defaultValue`. `orientation` (`vertical` by default) picks the arrow keys that move between triggers, and `disabled` disables every item.
