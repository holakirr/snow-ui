Search is a search field: a search icon, the text, an optional keyboard shortcut hint and a clear button that appears while the field has a value. It is the Figma "Search" in its two types, `gray` and `outline`; `size="lg"` is the 48px field at the top of the Figma SearchPopup.

```tsx
import { Search } from '@holakirr/snow-ui'

<Search aria-label="Search projects" shortcut={['/']} value={query} onValueChange={setQuery} />
```

<Primary />

## When to use

- Filtering or searching the content of a page, a list or a table.
- A search field in a header or a sidebar, with a hint for the shortcut that focuses it.

## When not to use

- Search across the app with grouped results and keyboard navigation: use [CommandPalette](?path=/docs/components-commandpalette--docs), whose `hotkey` opens it.
- A compact field that isn't a search: [InputSmall](?path=/docs/components-input-input-small--docs), the same field without icons.
- A form field: [Input](?path=/docs/components-input-input--docs).

## Anatomy

1. **Field** (`className`): the `<div>` with the fill, the stroke and the focus ring (`data-variant`, `data-size`).
2. **Search icon**: 16px (`sm`) or 24px (`lg`), Black/20%; Black/40% on hover and `primary` while the field has focus.
3. **Input** (`inputClassName`, and every prop not listed here): an `<input type="search">`. `ref` points at it. The browser's own clear and decoration icons are hidden.
4. **End content** (`endContent`, optional): extra content before the clear button, e.g. a filter button.
5. **Shortcut hint** (`shortcut`, optional): a [KBD](?path=/docs/components-text-kbd--docs) with the keys, shown while there is no clear button. It is only a hint: bind the shortcut in your app.
6. **Clear button**: shown while the field has a value and is neither disabled nor read-only. An XCircle icon, 16px (`sm`) or 20px (`lg`).
7. **In progress ring** (`status="progress"`, optional, added in 5.2): the turning ring of [Spinner](?path=/docs/components-spinner--docs) in place of the clear button or the hint, 16px (`sm`) or 20px (`lg`).

## States

- **Hover:** the variant's hover fill or stroke; the search icon turns Black/40%.
- **Focus:** while the input has focus, by mouse or keyboard, both types become Surface/1 with a 0.5px Black/40% stroke and the 4px Focus ring (the Figma "Focus"); the search icon turns `primary`. Text fields don't get the `focus-ring` outline. With more contrast the focus stroke is 2px (Black/80%, the stroke colour when read-only): the Figma 0.5px Black/40% stroke is 2.85:1 on the fill.
- **Typing:** a value replaces the shortcut hint with the clear button.
- **Disabled** (`disabled`): the whole field at 40% opacity, with no pointer events and no clear button. The kit uses 20% with the default arrow cursor: planned for 6.0.
- **Invalid** (`aria-invalid`): a 1px Secondary/Red stroke on both types, in every state (the kit's Error stroke; the kit draws no Error for Search, so it has no `Warning` icon, unlike Input).
- **Read-only** (`readOnly`): no clear button, and Escape doesn't clear.

<Canvas of={SearchStories.Typing} />

**In progress** (`status="progress"`, added in 5.2): while results load, the kit's In progress state: a turning ring in Black/100% (white in dark mode) takes the place of the clear button (or the shortcut hint), and the input gets `aria-busy="true"`; Escape still clears. The ring is `aria-hidden` and Search announces nothing itself: say "Loading" or the result count in your results region (a `role="status"` element), as [CommandPalette](?path=/docs/components-commandpalette--docs) does. It replaces a spinner of your own in `endContent`.

## Accessibility

- The input is `type="search"`, so its role is `searchbox`. Give it a name with `aria-label` or a [Label](?path=/docs/components-label--docs) with `htmlFor` and the same `id`: the placeholder ("Search" by default) is not a label.
- The clear button is a `<button type="button">` named by `clearLabel` ("Clear search" by default, also its `title`). After a click, the focus returns to the input.
- The shortcut hint is `aria-hidden`. If the shortcut matters to keyboard users, describe it elsewhere, e.g. with `aria-keyshortcuts` on the input.

### Keyboard

The `shortcut` keys are only a hint: Search doesn't bind them.

| Key | Action |
| --- | --- |
| Tab | move focus to the input, then to the controls in `endContent` and to the clear button (shown while the field has a value) |
| Escape | clear the field while it has a value: `onChange` and `onValueChange` get an empty value, then `onClear` runs, and the focus stays. Call `event.preventDefault()` in your `onKeyDown` to keep the value. On an empty field Search leaves Escape to your handlers |
| Enter, Space | on the clear button: clear the field; the focus returns to the input |
| Enter | in the input: submit the form it is in, when the form has a submit button or this is its only text field (the browser's implicit submission) |

### Deviations from the Figma kit

The full table is in the package README.

| Figma | Library | WCAG |
| --- | --- | --- |
| Shortcut hint in Black/20%: 1.6:1 | `text-secondary`, with no fill of its own (a second Black/4% layer on the hovered dark field took it under 4.5:1) | 1.4.3 |
| Clear button at 40% opacity: 2.85:1 | 60% (5.74:1), 80% on hover | 1.4.11 |
| Clear button: no focus state | on keyboard focus, full opacity and `focus-ring` (a 2px `black-80` outline: 12.6:1 light, 8.7:1 dark) | 2.4.7, 1.4.11 |

Known gaps with the default contrast, which keeps the Figma values: the Black/20% placeholder (it is never the field's only label) and the Black/4% fill of the `gray` field (1.1:1). With more contrast (`prefers-contrast: more` or `data-contrast="more"`; see [Contrast](?path=/docs/guides-contrast--docs)) the placeholder and the icon are Black/60% (at least 5.25:1; White/75% in dark mode) and both variants get a 1px `control-border` stroke (at least 3.3:1).

The clear button is a 16px icon with a 24×24px hit area (`hit-area`, WCAG 2.5.8), and the input fills the field's height, so the whole 28px field is its target.

## Localization and RTL

- Built-in strings: `messages.search.placeholder` ("Search") and `messages.search.clear` ("Clear search"). The `placeholder` and `clearLabel` props override them; see [Localization and RTL](?path=/docs/guides-localization-and-rtl--docs).
- The field is a flex row, so in right-to-left text the search icon is on the right and the hint or clear button on the left.

## Controlled and uncontrolled

Pass `defaultValue` to leave the value to the field, or `value` with `onChange(event)` or `onValueChange(value)` to control it. Clearing (the button or Escape) sets the input's value the way the browser does, so `onChange` and `onValueChange` both fire with an empty value, controlled or not; `onClear` runs after them.

## Do and don't

<DoDont>
<Do>

- Name the field with `aria-label` ("Search projects") or a visible label.
- Bind the key of the `shortcut` hint in your app, e.g. through CommandPalette's `hotkey`.
- Use `onValueChange` when you only need the text.
- Use `status="progress"` while results load, and `endContent` for a filter button next to the clear button.

</Do>
<Dont>

- Don't rely on the placeholder as the name.
- Don't add a second clear button: Search shows one while it has a value.
- Don't show a `shortcut` hint for a key the app doesn't bind.

</Dont>
</DoDont>
