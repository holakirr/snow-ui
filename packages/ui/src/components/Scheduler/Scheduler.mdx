Scheduler shows one week of timed events on an hour grid: seven day columns, one row per hour. A click on an hour cell or an event calls your handler; an event also opens a menu with its details. It has no Figma component and no state of its own: you pass the week (`currentDate`) and the events.

```tsx
import { type CalendarEvent, Scheduler } from '@holakirr/snow-ui'

const events: CalendarEvent[] = [
  { id: '1', title: 'Team meeting', date: new Date(2025, 0, 24, 10), endsAt: new Date(2025, 0, 24, 11, 30) },
]

<Scheduler
  currentDate={week}
  events={events}
  onDateClick={(date) => createEventAt(date)}
  onEventClick={(event) => select(event)}
/>
```

## When to use

- A week of meetings, bookings or shifts, where the user picks a free hour or opens an event.
- A desktop dashboard with room for a wide grid.

## When not to use

- Picking a date or a range: [Calendar](?path=/docs/components-calendar--docs).
- A list of upcoming events: [ListItem](?path=/docs/components-listitem--docs) rows or a [Table](?path=/docs/components-table--docs).
- Narrow screens: the grid has a fixed width of 871px.

## Anatomy

1. **Grid**: a `<div>` CSS grid with a 59px hour column and seven 100px day columns, 16px apart, and 48px rows. Other `div` props, `className` and `style` go to it.
2. **Day labels**: the header row, the short weekday and the day number in 12px `text-secondary`, with radius 4 and padding 2 / 4px. Today's label has a Secondary/Indigo fill with static black text.
3. **Day separators**: Black/4% vertical lines between the days.
4. **Hour labels**: 12px `text-secondary` hours in the locale's clock ("9 AM" in `en-US`). The rows run from 7 to 20 (8 pm) and grow to fit the events' start and end hours.
5. **Hour cells**: one per day and hour. A click calls `onDateClick`.
6. **Events** (`events`): Color 2 blocks with radius 4 and 4px padding: the title (truncated) and the start and end times in 12px static black, the times at 60%. An event sits in the cell of its start hour, moved down by its minutes, and is as tall as its duration (48px per hour, at least 48px). A click calls `onEventClick` and opens a [DropdownMenu](?path=/docs/components-dropdownmenu--docs) with `dropdownContentRenderer(event)`, or the title without one.
7. **Current time**: a Primary [Tag](?path=/docs/components-tag--docs) with the time and a Primary line across the grid, while the current time is within the grid's hours.

## Variants

`startOfWeek` sets the first day of the week, from `0` (Sunday) to `6`; the default is `1` (Monday).

### Events

An event is a `CalendarEvent`. Scheduler reads `id`, `title`, `date` (the start), `endsAt` and the optional `dropdownContentRenderer(event)`, which returns the content of the event's menu (details, "Edit" and "Share" actions…). The type's other fields (`description`, `participants`, `location`, `url`…) are for your own renderers. Events that start in the same hour of the same day overlap: each one is as wide as the cell.

## States

- **Today:** the day label on Secondary/Indigo.
- **Keyboard focus:** the `focus-ring` utility on hour cells and events.
- **Empty:** without events the grid still shows the hours from 7 to 20.
- **Now:** the current-time tag and line, placed by the hour and minute at render.

Cells and events have no hover style.

## Accessibility

- Every hour cell is a `div` with `role="button"` in the tab order, named by its date and time in the locale (`toLocaleString`). Enter or Space calls `onDateClick`. The default grid has 98 cells (7 days × 14 hours), so a keyboard user tabs through all of them to pass it.
- Every event is a `div` with `role="button"` in the tab order, inside its cell; its name is its text (the title and times). A click, Enter or Space calls `onEventClick` and opens its menu; in the menu the arrow keys move and Escape closes it and returns focus.
- The events are buttons inside the cell buttons: nested interactive controls, which some assistive technologies don't expose.
- The grid has no table or grid semantics: the day and hour labels are plain text, and the cells' names carry the date and time.

Deviations from the Figma kit (the full table is in the package README):

| Figma | Library | WCAG |
| --- | --- | --- |
| "Focus" effect: a 4px Black/4% ring (1.1:1) | `focus-ring`: the Figma ring plus a 2px `black-80` outline offset by 2px (12.6:1 light, 8.7:1 dark) | 2.4.7, 1.4.11 |
| Day and hour labels in Black/40%: 2.85:1 on white, 3.41:1 on #333 | `text-secondary` (5.74:1 light, 7.08:1 dark) | 1.4.3 |
| Today's day label: white on Secondary/Indigo, 2.06:1 | static black on Secondary/Indigo | 1.4.3 |
| Event times at 40% on Color 2 | 60% static black on Color 2 (5.5:1) | 1.4.3 |

## Localization and RTL

- Scheduler uses no `Messages` keys. The day labels, hour labels and cell names use the language of `SnowUIProvider`'s `locale` (`locale.code`), and `en-US` without one, so the server and the browser render the same text.
- Event times (`09:30`) and the current time (`9:30`) use a 24-hour clock in every locale; the hour labels follow the locale's clock.
- In right-to-left text the grid runs from the right: the hour column is on the right, and the day separators are placed from the end edge so they stay between the days.

## Controlled props

`currentDate` is controlled only: the grid shows the week that contains it, starting on `startOfWeek`. Scheduler has no navigation of its own, so move `currentDate` by seven days from your own previous / next buttons. `onDateClick` and `onEventClick` are required. `onDateClick` gets the cell's day with its hour set; the minutes and seconds come from `currentDate`. (A `defaultDate` and optional handlers need a breaking change, planned for the next major version.)

## Do and don't

<DoDont>
<Do>

- Keep `currentDate` in state and change it by a week from your own buttons.
- Give each event an `endsAt` after its `date`: the block's height is the duration.
- Use `dropdownContentRenderer` for an event's details and actions.
- Set a `SnowUIProvider` locale so the labels match the page's language.

</Do>
<Dont>

- Don't start two events in the same hour of a day: they overlap.
- Don't use Scheduler to pick a date: use Calendar.
- Don't put a Scheduler in a narrow column: it doesn't shrink.

</Dont>
</DoDont>
