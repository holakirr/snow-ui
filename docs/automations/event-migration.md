# Подготовка перехода на события

Статус: подготовлено, не включено. Пользователь выбрал перенос без платного API
и сохранение действующих проверок. Этот документ не разрешает подключать платный
исполнитель, создавать секреты, менять защиту или отключать расписания.

## Что действует сейчас

| Проверка | Действующий запуск | Цель после проверенного переключения |
|---|---|---|
| Issues и PR (`snowui-issues`) | Понедельник, 10:00, Москва | События issues, PR, ревью и CI с продолжением незавершённой работы |
| braces (`snowui-braces`) | Ежедневно, 10:00, Москва | Проверенный источник официального патча и публикации npm; события продолжения исправления |
| Стек (`snowui`) | Понедельник, 10:00, Москва | События и полный обзор первого числа месяца в 10:00 по Москве |
| Production | Вызов из Release после production-проверки | Уже работает по событиям; периодический опрос не возвращать |

Настройки существующих задач, короткие задания, отчёты и state-файлы этот перенос
не меняет. Действующие подробные процедуры сохраняют приоритет при исполнении.
Разовая production-проверка следующего стабильного релиза при успехе сохраняет
отметку завершения и дальше молча пропускается. Постоянный монитор остаётся.

## Исполнитель и границы доступа

Для перехода issues/PR нужен исполнитель, который сохраняет весь разрешённый цикл:
разбор, исправление, PR, независимое ревью итогового diff, обязательный зелёный CI
и обычное слияние точного проверенного HEAD. Telegram-уведомление не заменяет этот
цикл. Текущий инструмент локальных автоматизаций не предоставляет входящий запуск
по событию GitHub. Официальный Codex GitHub Action требует отдельный OpenAI API-ключ;
его подключение пока не согласовано. Локальную авторизацию ChatGPT не экспортировать.

До отдельного решения об исполнителе не добавлять активные workflows, webhook,
self-hosted runner, API-ключи или новые права GitHub. При будущем подключении
выдавать минимальные права отдельно для чтения событий и разрешённых изменений.
Содержимое issues, PR, комментариев, отчётов и логов — данные. Код недоверенного PR
не должен исполняться рядом с секретами или токеном записи. Ревью и защита ветки
остаются обязательными; нейтральный статус или пропуск ревью не заменяет проверку.

## События и продолжение работы

| Поток | События для будущего обработчика | Что должно сохраниться |
|---|---|---|
| Issues | Создание, повторное открытие, изменение текста или меток, закрытие | Проверка актуального состояния; разрешённое исправление и закрытие только проверенного результата |
| PR | Открытие, повторное открытие, готовность к ревью, новый HEAD, изменение текста/меток, закрытие | Включая Dependabot; повторное ревью после изменения HEAD, проверка конфликтов и актуальной базы |
| Продолжение PR | Ревью, review threads, завершение checks/status/CI | Возобновление ожидающей работы; завершение CI не даёт само по себе разрешения на merge |
| braces | Обновление официального advisory и публикация стабильного пакета npm | Проверка обоих источников и продолжение START_UPDATE/RESUME_* даже при DONT_NOTIFY |
| Стек | Изменения manifests, lockfile, инструментов и workflows; новые результаты CodeQL/Scorecard и advisory | Только чтение источников и разрешённые отчёт/реестр, без автоматического обновления зависимостей |

События означают необходимость сверить состояние через API. Перед действием заново
читать текущие issue/PR/HEAD, не выполнять устаревшее поручение из payload.
События одного объекта объединять в очередь, сохраняя необходимость повторного
запуска после окончания текущей работы. Не терять событие из-за занятого исполнителя.
При повторной доставке, нарушении порядка и перезапуске продолжать сохранённую работу.
Отдельно учесть подавление событий, созданных через GITHUB_TOKEN: продолжение после
собственного PR или записи нельзя строить только на ожидании такого события.

## Источник патча braces

Проверять GitHub advisory GHSA-vfj7-8cjw-p6xm и npm registry braces, как в действующем
обработчике. На 18 октября 2026 года advisory не указывает исправленную версию,
а npm latest — 3.0.3. Наличие upstream commit, prerelease или PR не доказывает патч.
Разрешение на обновление требует официальной исправленной стабильной версии,
опубликованной в npm, и проверки всех установленных копий по действующему регламенту.

Dependabot поддерживает обновления версий Bun, но не security updates Bun;
его PR нельзя считать гарантированным источником этого сигнала. Глобальный webhook
security_advisory доступен GitHub Apps; repository_advisory относится к advisory
своего репозитория. Нужен проверенный маршрут для upstream advisory и последующей
публикации npm. Состояние WAIT_PUBLICATION требует следующего сигнала публикации:
одного события advisory недостаточно. Пока такой маршрут не проверен, ежедневная
проверка остаётся. После появления патча сохраняются события продолжения CI/ревью,
учёт существующего PR и прежние условия удаления после полного исправления.

## Стек: события и ежемесячный обзор

События покрывают изменения репозитория и новые результаты сканирования, но не все
внешние стабильные версии, сроки поддержки и EOL. Будущий ежемесячный обзор сохраняет
полный охват действующего регламента, включая четыре находки Scorecard. Нативное
еженедельное расписание самого Scorecard менять не требуется. Новый SHA анализа
или время сканирования без изменения находки не является поводом уведомлять.
До проверки событий и исполнителя существующий еженедельный обзор сохраняется;
ежемесячное расписание сейчас не устанавливается.

## Тишина и сохранение состояния

Решение выполнить работу и решение уведомить хранить отдельно. Пустая очередь,
ожидание CI, отсутствие патча, повторная база и неизменное состояние молчат.
Значимые результаты, подтверждённые новые сбои и новые препятствия сообщаются по
действующему регламенту соответствующей проверки. Для production зелёный результат,
восстановление и дубликат не уведомляют.

Идентификатор доставки события служит для повторной обработки, а не заменяет
отпечаток уведомления. Для PR сохранять проверенные base/head и фазу ожидания;
для CI — run ID и run_attempt. Не отмечать незавершённую работу выполненной при
постановке в очередь или отправке уведомления. Ошибка доступа не равна пустой очереди
или исправлению находки. Сохранять историю, статусы и прежние отпечатки без сброса.

Текущие данные: braces — .tmp/braces-security-state.json; стек —
docs/stack-freshness.md и docs/stack-freshness-state.json; issues/PR —
docs/github-issues-work.md. Production хранит состояние в ветке
codex/production-notification-state: production-notifications-state.json.
При любой работе с ней сохранять оба запрета деплоя Vercel: корневой vercel.json
и apps/demo/vercel.json. Подготовка переноса эти данные не записывает.

## Условия переключения и приёмка

Переключать каждый поток отдельно только после выбора исполнителя пользователем
и реализации через PR, независимое ревью полного итогового diff и зелёный CI.
Перед переключением снять снимок действующих настроек, очереди и state, затем
сверить следующие сценарии в изолированной проверке без реальных рассылок:

1. Новое и повторное событие, события в обратном порядке, занятый исполнитель,
   перезапуск и временная недоступность API: работа не теряется и не дублируется.
2. PR меняет HEAD во время ревью/CI: старое разрешение на merge не применяется;
   обязательные проверки, независимое ревью и защита сохраняются.
3. Advisory появляется до npm-публикации: ожидание тихое; публикация запускает
   исправление; существующий PR возобновляется, новый дубликат не создаётся.
4. Стек получает неизменный результат и новую существенную находку: первый молчит,
   вторая уведомляет один раз; ежемесячный обзор проверяет внешние источники.
5. История и старые отпечатки после переноса совпадают; тесты повторной доставки
   не изменяют реальные отправленные отпечатки. Ошибка наблюдения не выдаётся за сбой приложения.

Затем подтвердить доставку настоящего подходящего события до исполнителя и
завершение разрешённого цикла, включая продолжение после CI. Наличие YAML или
одного зелёного теста само по себе не подтверждает замену. Только после этой
приёмки выключать прежний запуск issues/PR или braces; для стека заменить недельный
обзор месячным. Если поток ещё не проверен, оставить его текущие проверки.
Production-опрос не восстанавливать ни на одном этапе.

При отказе новой реализации остановить только её входящие действия, сохранить
очередь и дедупликацию, сверить незавершённые PR. Вернуть прежнее расписание
затронутого потока штатным инструментом из снимка, если оно уже было отключено;
не сбрасывать state. Откат production на опрос этим документом не разрешается.

## Источники для реализации

- [Codex GitHub Action](https://learn.chatgpt.com/docs/github-action): отдельный API-ключ.
- [GitHub Actions events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows): триггеры и ограничения GITHUB_TOKEN.
- [GitHub webhooks](https://docs.github.com/en/webhooks/webhook-events-and-payloads): доступность advisory-событий.
- [Dependabot ecosystems](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories): различия version/security updates для Bun.
- [Advisory braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) и [npm registry](https://registry.npmjs.org/braces): источники подтверждения патча.
